Expects `form` and `formset` in context; renders no
tag or csrf token of its own, since the two callers differ there. Paired with _poll_config_tablist.html for the matching tab strip; a caller includes both inside its own , this file's five panels being exactly what that form submits. Each panel ends with its own copy of the submit button (labelled by `poll`'s presence, same test the tablist and "Nature du scrutin" below already use to tell the two callers apart) rather than one shared button placed after the include: a single button living outside all five `[data-tabs-panel]` elements is never hidden by static/js/tabs.js's tab switching, so on screen 2 — which has a sixth, "Actions" tab beyond these five — it kept surfacing there too, above "Annonce" et al., with nothing to save on that tab. Putting a copy inside each panel makes it hide and show with its own tab like every other field, and costs nothing on poll_create.html, which has no sixth tab for the old placement to leak into. R-3.1's dozen-odd fields is one long scroll as a flat sequence of fieldsets, so they are grouped into tabs (static/js/tabs.js) instead. The grouping is cosmetic only: every field posts exactly as before, in the same fieldset, so a screen reader or search-engine crawl of the no-JS rendering — which shows every panel stacked, open, in this same order — sees the identical form R-14.1 already required. tabs.js decides which tab opens first by scanning for a `.error` inside each panel, so a rejected submission still lands on the field that failed instead of a panel nobody opens. Everything on screen 2 that is its own POST target rather than a field of `form` — "Annonce", "Ouverture" and "Enregistrer comme modèle" in _poll_config_actions_panel.html, "Images des propositions" in _poll_config_images_panel.html — lives outside this file instead, two more panels poll_config.html includes as this 's siblings, never inside it: HTML forms do not nest, and folded in here they would render outside every `[data-tabs-panel]`, invisible to tabs.js and so stuck on screen no matter which tab is open — the bug that split exists to avoid. poll_create.html has neither panel: none of those actions make sense before the poll exists. {% endcomment %} {% if form.non_field_errors %} {% for message in form.non_field_errors %}
